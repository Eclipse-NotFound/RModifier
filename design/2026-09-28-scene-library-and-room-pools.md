# 全场景房间管理与自建房间混抽

## 用户决定与交付行为

用户要求所有场景的房间都可显示、修改、新建、保存，保留原 Flash UI 和预渲染，不要求编程基础。保存使用副本，游戏原图保留。游戏接入最终明确为：把自建房间加入原版房间池，混合随机出现，现有角色照常进入原有地区。

原页面默认只打开 rooms_plant.xml，造成“只有工厂”的观感。新增 Flash 内“场景与房间 · 我的房间池”，动态发现当前 Rooms 目录：本机 31 份文件、662 间房间，包含随机地区、固定剧情地区及模板。场景使用游戏中文名称，房间保留原有身份名称并提供地形缩略图、搜索、分页和房间用途。

操作路径：

1. 在地图页点击“场景与房间 · 我的房间池”，选择场景与房间，点击“编辑所选房间”。
2. 用原来的素材面板绘制；原预渲染、图层、撤销/重做继续使用。
3. 在场景窗口点击“新建房间”或“复制房间”；可输入名称后改名。新房间自带地板，固定布局的新房间自动使用空位置。
4. 点击原“保存”按钮。首次编辑原图自动保存到“我的房间池”；也可在场景窗口命名后“创建房间池副本”。“另存”保留任意 XML 工作副本导出。
5. 打开自己的池，点击“保存并加入游戏混抽”。首次安装地图模块需重启游戏，之后配置变化由模块读取，已生成的地图保持原样，地区下次重新生成才使用新池。
6. 选择相应游戏原图，点击“停止本地区的自建房间混抽”，下一次生成恢复原版抽取，自己的池仍保留。

每个原始地区文件可启用一份自建池。8 组随机地区文件对应 10 个游戏地区身份；军事基地/地堡、π避难厩两种状态分别共用来源。固定剧情场景照样浏览、编辑和保存副本，不作为随机池发布。

## 文件与运行契约

- `desktop/map/scenes.json`：从 1.02 GameData 与中文游戏词典提取显示名称和地区关系；实际目录仍动态扫描。
- `desktop/map/scene-library.cjs`：原图/副本目录、创建时原始基线、保存、只发布变化房间、关联背景房间复制。
- `desktop/map/native-ui-module.cjs`：串行场景/房间命令；按文件保存恢复草稿；切换后新 documentId 拒绝旧事件。显式文件“载入”读取磁盘版，场景库切换恢复草稿。
- `desktop/map/pool-runtime.cjs`：用户点击发布时核对组件，再安装 `release/MapPoolMod.swf`，按完整入口 `RModifier|MapPoolMod|1|0|0` 更新 `mods/ModLoader/supported-mods.txt` 和 `mods/loader-manifest.txt`；事务备份在 `backups/map-runtime/`。失败回退自身已写且未被别人改动的文件。不改 pfe.swf、其他模组源码或正式存档。
- 工作副本：`projects/maps/library/<uuid>.xml`；初始基线 `<uuid>.base.xml`；目录 `index.json`。显示名称与文件身份分离。
- 游戏副本：`projects/maps/published/<uuid>/<sha256>.xml`；设置 `config/map-pools.json`。保存编辑稿不会自动更新游戏池，发布才更新。
- `MapPoolMod 0.1.0`：只在 1.02 启用；核对游戏副本 SHA256，向已加载的 LandLoader.allroom、当前 Game.lands 的 LandAct.allroom 追加具有独立名字的房间。保留原房间以及已有 Land 对象，新建/读档后的 Game 重新绑定池。没有自动开档、传送或测试代码。
- `MapPoolProbeMod` 只在 build/out 隔离测试中使用，不进入 component 或 release。

未修改的原房间不再追加一遍，避免无意改变原房间相对抽取权重。普通房间及原有分区随机槽可作为新变体；入口、结束、背景等专用房间不会独立混抽。被新增变体引用的背景房间会连同引用一起复制并使用新身份。生成仍遵循原版阶段、分区、限次和邻接规则，不保证每一层都出现每个自建房间。

## 本轮问题与修正

场景切换时，600ms 自动恢复可能在目标草稿读出前写入新打开的干净文档。已在切换事务内暂停恢复计时，先恢复目标草稿再显示；跨场景重返、撤销历史与过期消息测试通过。此为本模块实现问题。

测试夹具首次把输出写到 AIR 的 app:/ 地址，引发 fileWriteResource；改为指向独立测试目录的本机 File 路径。实际地图模块仅从 app:/ 读取发布文件。另修正夹具用 listLocs 枚举随机地区的问题，随机地图实际使用 locs[x][y][z]。保存测试先关闭开场界面，解除测试实例的 noAct，再使用普通存档接口。夹具失败未算业务通过，失败记录保留在 build/out。

ui-design 使用版本 `2026-09-17.1`，SKILL.md 指纹 `a51eda29c31dbb5c5771cd924728bd4d8f92c191b3341b950d448a0cd51c84d8`。读取其《实战验证》参考；实际采用沿用原界面、使用真实场景内容、按完整用户操作流程检验、实际渲染后检查。未做真人无编程基础用户试用；本报告不代表所有平台或DPI组合已验。

尚未认证 DLC、联机、与所有模组的长期并用、玩家任意自建房间的通路/剧情正确性。当前运行模块验证的是游戏 1.02 单人混抽与读档；固定剧情图不以混抽方式覆盖原版。
