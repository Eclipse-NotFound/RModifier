# RModifier 构建与三方整合经验

日期：2026-09-28。本项目实际实施记录，不替代最终产物验收。

## 并行交付先固定接口与写入边界

地图与台词都曾提供完整宿主原型，造成 main/preload/shell/documents 接口不兼容。总整合先完整保全混合文件到 `build/out/coordination/20260928-133238`，然后将主宿主统一归一人，两个页面各自拥有服务、UI与测试。公共契约固定为 `workshop` 具名方法与 `RMHost.register/state`，不再让三方交替覆盖 shell。

保存回复绑定发起时的文档与修订；取消或等待期间继续编辑不视为已保存。关闭窗口必须等待持久恢复完成，并再次检查期间是否出现新修改。切换游戏根会换 IPC 会话标识，旧页面的延迟请求不能写入新选中的游戏。

## 打包报告必须记录实际进入包的组件

一次候选打包压缩期间，地图方重建了 SceneHost：发行目录实际组件为 `ae9ff8f1...9830a0e1`，源目录新组件为 `a1c0a4ca...d9eb93cb`。旧脚本在压缩结束后读取源目录 hash，因而不能证明 EXE 内容。该候选只用于打包结构试运行，没有作为最终发布产物。

修正为：冻结三方写入；构建前记录全部运行输入；构建后逐项确认输入未变；从实际发行目录读取组件指纹并与冻结清单比对；最后实际启动单文件 EXE。修改代码后必须重新构建，不能靠更新报告认证旧包。

## 本机工具与网络绕行

electron-builder 26.15.3 固定于 package-lock。官方 GitHub 组件下载曾出现连接超时；从镜像取得同名文件后，先与安装的打包器源码中固定的 SHA-256 核对，再解压使用：

- NSIS 3.0.4.1：`9877df902530f96357d13a7a31ae2b9df67f48b11ffc9a1700a7c961574ec5fa`。
- NSIS resources 3.4.1：`593a9a92ef958321293ac6a2ee61e64bf1bd543142a5bd6b3d310709cc924103`。

本地配置使用该版本支持的 `ELECTRON_BUILDER_NSIS_DIR`、`ELECTRON_BUILDER_NSIS_RESOURCES_DIR` 与 `ELECTRON_BUILDER_7ZIP_PATH`，不修改 node_modules 源码，不关闭完整性检查。复现入口为 `tools/prepare-packager.ps1`；其他版本必须重新核对其官方固定校验值。

## 单文件验证与游戏隔离

真实 portable EXE 放入只有一个文件的中文空格目录，通过本机调试端口连接其实际 UI；检查三页、隐藏 AIR、重复启动、持久保存和回收进程。仅测试 unpacked 目录不足以覆盖 portable 释放路径与参数转发。

用户数据始终写持久工程目录；临时释放目录只放程序。游戏素材由显式 gameRoot 提供。测试使用明确 gameRoot + 唯一 testRoot；AIR 使用唯一应用 ID，不能混入真实 `pfe` 存储。每个测试只停止自己记录的进程。

## 原 Flash 界面的实际承载与回归

0.3.0 接入采用一个 BaseWindow 与常驻 WebContentsView，地图激活时将网页裁到顶部导航，AIR 窗口填充下方区域。原型中 SetParent/WS_CHILD 的窗口关系看似正确，实际像素却为空白；最终使用有主窗口所有者的无边框 popup，去掉独立任务栏入口且不置顶。不能仅凭 HWND/parent 元数据宣称画面已经成功嵌入。窗口适配器只管理布局与焦点，AIR 的启动和关闭仍由地图模块负责。

本机 200% 系统缩放时，Win32 的地图区宽度为 2534 物理像素，AIR Stage 宽度却是 1267 逻辑点。单纯再乘 deviceScale 会重复放大。组件使用实际 clientWidth/stageWidth 的比例消除重复缩放，并以真实窗口截图确认正常字号与适应模式。此证据不覆盖不同缩放显示器间的拖动，也不等于已验证真实中文输入法组合。

第一份 0.3.0 单文件候选在协议层宿主测试通过后，真实鼠标点击原“切换层”仍触发 #1009。原随机房间集合没有固定地图的 mapArr，原按钮监听器却会读取它；错误先发生，后来保存才显示出来。因此必须对照 fatal 文件时间与实际动作，不能把最后看到错误的保存动作当成根因。新增回归从原按钮 CLICK 进入，覆盖无选中对象、固定上下层、从固定图转回随机集合、原预览打开后的保存取消与成功。该候选拒收，修复后重新构建和验收，不能更新报告来认证旧 EXE。

实际 ASAR 核对在 Windows 上需将内部路径转换为 path.sep 再调用 asar.extractFile；只检查 unpacked 资源目录不能证明打包的宿主 JavaScript 与源文件一致。electron-builder 会归一化 package.json，故其关键元数据按字段比对，其他运行源码按 SHA-256 比对。

## 验证范围

这次验证发生在 Windows、Electron 44.4.5、electron-builder 26.15.3、Remains 1.02。本机受限桌面环境曾使 Electron 渲染进程无法启动，正常桌面权限后通过；不能把它推广为所有 GPU 崩溃都由权限造成。实际单文件可运行不等于用户正式游戏已重启加载，也不等于静态地图预览覆盖实战剧情。
