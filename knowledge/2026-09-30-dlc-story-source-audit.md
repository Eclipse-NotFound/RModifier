# DLC 剧情、场景入口与存档：1.02 源码调查

日期：2026-09-30。范围：供 Remains 独立 DLC 图形编辑器规划使用；按用户最新要求，它与 RModifier 现有地图编辑窗口分开，可复用底层能力。本篇负责剧情与世界进度，不代替新身体、动画、AI 的专项调查。

证据等级：**源码已证**指本次直接读取的 1.02 反编译文本与当前安装 XML；**需原型**指据此提出的实现路线，尚未编写或进入游戏验证。未启动游戏，未修改游戏、编辑器源码、配置、SWF、存档或公共状态。只新增本文。没有把旧 MEMORY 中的版本当作当前发布证明。

下文 `S/` 的完整工作区相对前缀为 `game-reference/decompiled/1.02/src102/scripts/`。例如 `S/fe/serv/Script.as:123–195` 是该文件的实际行号。`Rooms/` 与 `text_zh.xml` 指安装根目录。本次没有验证当前已打补丁 SWF 与参考源码逐方法一致。

## 1. 结论与实现方向

**可以做图形化 DLC 剧情编辑器，但不能只在现有地图 XML 和随机台词页上加表单。** 原版已有触发区域、对象事件、顺序动作、任务阶段、奖励、地区转移及进度存档；它缺少通用的“玩家选回复 → 条件分支 → 后果”解释器和选择界面。应把这些能力收进一个项目模型，以新增通用剧情运行模块补齐分支与持久化，再与地图、角色、物品编辑共享稳定引用。此路线是建议，尚未验证接入时机与模块接口。

尤其要区分三件事：

| 用户想编辑的内容 | 原版实现 | 对编辑器的含义 |
|---|---|---|
| 角色随机短句 | `replic` 语料与单位事件，现有台词工坊服务这一层 | 不承载任务选择与后果。参照公共审计 `shared-knowledge/ui-systems/discoveries/random-barks-runtime-source-audit-2026-09-27.md`；本篇未重审全部随机语料 |
| 剧情对白 | 语言 XML 的 `txt/n/r`，按顺序播完；NPC 条件决定播放哪段 | 可以制作“谁说什么、头像、顺序、显示效果”；还不是可选回复树 |
| 分支剧情 | 条件散在 NPC、任务和写死 AS3 特例中，没有统一图形可编辑模型 | 首版需要显式的条件、选择、变量、后果及恢复规则；不能导出虚构的 `<if>`、`<choice>` 标签期待原生解释器认识 |

核心证据：`S/fe/inter/GUI.as:1720–1724,1744–1885`；`S/fe/serv/Script.as:64–119,123–195,199–561`；`S/fe/serv/NPC.as:262–416`。

## 2. 什么已外置，什么仍在 SWF 中

| 内容 | 当前数据位置、装配方式 | 已证的边界 |

本次只读解析数量：`GameData.d` 有 31 个直接 `land`、54 个 `npc`、97 个 NPC `dial`、55 个直接全局 `scr`、58 个 `quest`；另有 2 个 `land1`，不计入 `World` 遍历的 `land`。当前简中有 259 个包含 `n/r` 的 `txt`，共 1,930 行 `r`；其属性只有 `p/push/mod/m/v/s1…s5`，子节点为 `t` 与 `r`，未见选择或跳转字段。此为结构统计，不代表全部剧情可达性已核验。

## 3. 原生事件与顺序动作可以复用的部分

| 触发入口 | 定义方式 | 原始证据及限制 |
|---|---|---|
| 玩家进入/离开区域 | `area` 的内联 `<scr>`、`scr`/`scrout` 引用 | `S/fe/loc/Area.as:136–157,285–373`。进入/离开是边沿事件；只在区域启用且房间活动时检查 |
| 按按钮、开箱、开门/关门、触碰、物体损毁 | Box 的 `scr` 与 `eve=open/close/touch/die`，或对应引用属性 | `S/fe/loc/Box.as:313–359`。实际交互还会先经历钥匙、锁、陷阱、消耗品等门槛；不是点击即总会触发 |
| 单位死亡/警戒 | 单位地图 XML 的 `scr` 或 `alarm` | `S/fe/unit/Unit.as:1563–1587`。同名 `scr` 在单位上默认是死亡事件，不能按箱子“互动”解释 |
| 在本地区获得物品 | 地区 `<scr eve='take' item='...'>` | `S/fe/loc/Land.as:141–148`、`S/fe/unit/Invent.as:1554–1559`。只查当前地区 `itemScripts`；普通物品/书/道具分支通常在原库存为零时才调用，不能泛称“每拿一件都触发”（`:1188–1227`） |
| 与 NPC 互动 | 按 NPC 定义选择合格 `dial`，可接 `scr/reward` | `S/fe/serv/NPC.as:205–246,262–416`。这一步的“选择”由状态筛选自动完成，不是玩家点击若干回复 |
| 任务或子阶段完成 | `Quest.close` 后 `enddial/endscr` | `S/fe/loc/Quest.as:603–705`，完成保护防止同一 Quest 实例重复发完成奖励 |

**源码已证：** `Script` 支持 `<scr act='...'>` 单步或 `<scr><s .../></scr>` 顺序步。它只取 `act/targ/val/t/n/opt1/opt2`；延时 `t` 乘 `World.fps` 转为帧数。无计时的脚本立即全跑；有延时或对白的脚本逐步执行。目标命令走 `owner` 或 `land.uidObjs`，全局命令走另一套固定分发。证据：`S/fe/serv/Script.as:32–119,123–195,218–235`。

可封装为易懂积木的原生动作包括：给/扣物品、经验、接任务、显示/完成子目标、改进度标记、开关/解锁对象、显示对白、镜头/音乐/等待、解锁地区、转移地区。分别见 `Script.as:300–335,337–398,408–467` 及对象 `command`；不能把所有动作对任意对象开放。

建议自动生成并隐藏 `uid/code`：`uid` 在一个 Land 内供剧情寻址，`code` 在 `Game.objs` 中供存档恢复，两者职责不同。复制房间/物体时保留旧 `code` 会把不同实例错误连到同一存档状态；重复 `uid` 则覆盖前一目标。原始注册都是直接赋值，没有自动命名空间：`S/fe/loc/Location.as:1146–1152,1240–1247,1997–1999,2057–2072,3552–3559`。

若直接导出原生 XML，还需处理属性“存在即真”的怪癖：例如 `Area.trig`、`LandAct.rnd`、`Quest.invis/hidden` 看的是属性是否存在，写 `trig='0'` 不等于关闭。证据：`S/fe/loc/Area.as:132–135`；`S/fe/loc/LandAct.as:131–134`；`S/fe/loc/Quest.as:177–184`。图形界面应显示开关并正确省略属性。

## 4. 原生对白没有回复分支

**源码已证：** `GUI.dialText` 用对白 ID 找 `Res.d.txt`，取 `n[0]`，再按 `r[n]` 取下一行；支持头像、追加行、文字样式、玩家姓名和按键占位。`Script.step` 只在按键后把 `dial_n` 加一；跳过键把它设为大值以结束，没有选项 ID、目的节点或选择结果返回。

证据：`S/fe/inter/GUI.as:1744–1885`；`S/fe/serv/Script.as:146–195,260–271`。简中 `text_zh.xml:4026–4043` 虽然出现“你一定要去中心城吗？”和“一定要去”，两句都是固定 `r`，并不是“去/不去”按钮。

`NPC.check` 可以筛玩家等级、交易技能、某个 trigger 值、前一段对话、某地区是否开放、护甲、宠物、活动任务、可见子目标；它没有自由组合的 AND/OR 条件树。执行时把对白插到动作前，再追加 `dial_<id>=1` 与 `checkall`。证据：`S/fe/serv/NPC.as:278–367`。

该函数的反编译输出在 `:274–331` 存在 `while(true)`/`break` 重构异常。可以确认它读取哪些条件与安排哪些动作，不能据此声称实际无限循环，也不能据此完全认证多个同时满足的对白的优先规则。

**需原型：** 新增回复选择界面与通用剧情执行器，至少返回稳定的 `choiceId`，允许每选项条件、锁定原因、后续节点；在“关闭原版对白显示”设置下，也必须保证不可跳过必须作出的 DLC 选择。原 `World.dialOn` 会直接跳过 `dialog` 的显示等待（`Script.as:260–271`），不宜照搬用于分支选择。

## 5. 可核对的完整原版剧情链：获得暗黑之书

这是“触发条件 → 自动选中对白 → 任务推进 → 地区开放/转移 → 关键物品 → 完成奖励”的完整链。**没有可核实的原版玩家多选回复节点，不能为满足例子而虚构一个。**

| 步骤 | 实际内容 | 原始证据 |
|---|---|---|
| 1. 拾取前提 | `mtn` 的 bossalicorn 携带重要物品 `amul_al`；首次拿到时触发当前地区的拾物脚本 | `Rooms/rooms_mtn.xml:284–287`；`S/fe/loc/Land.as:141–148`；`S/fe/unit/Invent.as:1209–1214,1554–1559` |
| 2. 登记新任务 | 拾物脚本结束旧 `storyMane`、播放 `maneDialAmul`、设 `story_canter=1`、接 `storyCanter`，完成当前地区并恢复控制 | `S/fe/GameData.as:437–450` |
| 3. 玩家回基地找 NPC | `rooms_rbl` 有 `npc='calam2'` 实例。该 NPC 的 `dialCanter1` 要求 `story_canter`，且该对白未播过；语言文件包含全段固定话语 | `Rooms/rooms_rbl.xml:265`；`S/fe/GameData.as:677–688`；`S/fe/serv/NPC.as:278–298`；`text_zh.xml:4026` 起 |

| 6. 场景触发进度 | 中心城起始区域 `trig_canterBegin1` 进入触发 `canterStory1`，完成子目标 2，播放进入对白。区域具有 `trig` 与 `uid`，用全局进度防止重复进入重跑 | `Rooms/rooms_canter.xml:4997`；`S/fe/GameData.as:1381–1384`；`S/fe/loc/Area.as:354–367` |

| 8. 完成与后续 | 在 `minst` 首次取得 blackbook 后完成子目标 4及整项 storyCanter、播放对白、接 storyHome、设 story_book=1，并让 minstComm 检查新状态 | `S/fe/GameData.as:546–557` |
| 9. 奖励与持久化 | storyCanter 定义奖励 50,000 XP；`Quest.close` 防重复、改变状态并发奖励。任务状态、地区开放/访问状态、标记分别保存 | `S/fe/GameData.as:1772–1777`；`S/fe/loc/Quest.as:603–658`；`S/fe/loc/Game.as:127–157`；`S/fe/loc/LandAct.as:267–299` |

此例的意义不是推荐照抄原剧情，而是展示**同一条内容链横跨房间实例、地区定义、任务定义、NPC 条件、语言文本、界面和存档**。编辑器需要从任一条目跳转到所有引用，并在改名/删除时一次更新或阻止破坏性引用。

另一个已证条件分支是病人医治：`NPC.patient()` 按 `rep`、医学技能、疫苗库存、`patient_tr2` 决定不同对白和阶段。无足够技能播 `dialPatient2`；技能足够则登记 `patient_tr1` 并显示找疫苗目标；有疫苗时扣一件、登记 `patient_tr2='wait'`、完成阶段 3。这里判断流程**写死在 AS3**，不是通用对白 XML。证据：`S/fe/GameData.as:1112–1114,1846–1850`；`S/fe/serv/NPC.as:570–620`。`wait` 会在 `Game.refillVendors` 改为 1（`S/fe/loc/Game.as:508–524`），不能误解为经过指定现实时间。

## 6. 新地区的入口需要单独设计

**源码已证：** 加载器和 `Game` 遍历所有 `GameData.d.land`，因此定义可作为注册入口；`LandAct` 持有布局、出生房、已开放/访问/完成等状态（`S/fe/loc/LandAct.as:102–181,267–299`）。但 `World.init2` 建加载器早于正常场景生成，所以运行扩展必须确认注册时机；迟到的定义不会自动补出已经创建的 `game.lands`。

原世界地图只查 `visWMap[land.id]` 已存在的显示实例，没有据每个 `land` 动态创建按钮；没有实例的新增地区不会自动出现在原图上。证据：`S/fe/inter/PipPageInfo.as:152–198`。可选实现是新增 DLC 目的地列表、基地互动入口或可配置传送门；具体需原型，不建议让内容作者自行改 Flash 地图时间轴。

转移也不等于无条件跳到地图：`gotoLand` 会检查角色状态和超重门槛，写待转移 ID 后由世界处理退出/进入；`beginMission` 会请求重建非基地地区（`S/fe/loc/Game.as:425–461`）。新场景要同时配置“进入”和“返回”路径，模拟角色未解锁、超重、重复进入、从场景读档与模块暂不可用时的行为。

`Game.Encounter`、`NPC.refresh`、结局界面均有原故事 ID 的硬编码分支：前者重定向特定地区；中者依 `storm` 等标记切换 NPC 可见性；后者用声望切换原结局文案。证据：`S/fe/loc/Game.as:405–423`；`S/fe/serv/NPC.as:134–195`；`S/fe/World.as:1606–1625`。**新 DLC 应用自己的命名空间与条件系统，不能把“本章结束”映射为原版 `endgame`。**

## 7. 分支后果与存档恢复

| 状态 | 原生保存/恢复 | 对 DLC 编辑器的要求 |
|---|---|---|
| 全局进度标记 | `Game.triggers` 整组复制保存，读档复制回来；值可以是数字或字符串 | 用项目专属稳定键；UI 显示有意义的名字、真假/枚举/计数类型，避免作者手填与原版冲突。证据 `Game.as:135–138,240–245,676–678` |
| 任务与子目标 | 保存 id/state/est/gived/invis、子目标字典；读档依据当前 GameData 重新创建 | 任务改显示名不应改 ID。增删/迁移子目标要有版本迁移；原版已有 inactive/active/complete 的使用，任意新增“失败、放弃、互斥关闭”不能假定原界面会理解。证据 `Quest.as:85–118,257–289`；`Game.as:537–565` |
| 地区开放与访问 | 保存 access/visited/passed/阶段/检查点 | 与任务/选择状态联动；不要只在当场把门画成打开。证据 `LandAct.as:267–299` |
| 固定场景对象 | 用全局 code 写 `Game.objs`，重新创建时读；只有登记 `saves` 的对象会保存 | 保持对象身份并按后果还原。随机地区的 `Land.saveObjs` 直接返回，不能承诺某个随机房的门/敌人会按原样保存。证据 `Location.as:1997–1999,2057–2072,3552–3559`；`Land.as:1189–1216` |
| NPC 状态 | 按当前 NPC 定义重新创建，再应用保存的 rep；其他可见状态常由特例刷新 | 需要定义级迁移与可配置可见条件，不能把所有运行内存当成已保存。证据 `Game.as:230–238`；`NPC.as:95–99,134–195` |
| 正在播到第几句/正在等哪条动作 | `Script` 的 ncom/tcom/dial_n/running 在 `Game.save` 与 `Quest.save` 没有对应保存项 | 新分支模块必须定义安全提交点，保证奖励不重复、已选回复不丢失。证据 `Script.as:20–30,123–195` 与 `Game.as:86–162` |

不能由最后一项直接声称原游戏“对话中必然坏档”：原 `controlOff()` 会设 `pip.noAct=true`，正常 `saveGame` 因此返回；`controlOn()` 解除。证据：`S/fe/unit/UnitPlayer.as:2037–2065`；`S/fe/World.as:1649–1684`。这里的实质要求是**新增选择界面必须继承保存/控制互斥，并给异常中断、脚本跨场景、扩展数据恢复制定策略**，不是已有故障的实测结论。

有两条尤其需做原型验证：

1. `Area` 在启动脚本前就将一次性 trigger 设为 1（`Area.as:354–361`）。如果扩展执行器中途失败，重入不能简单依赖该区域再触发；应保存“事件已完成”与“事件执行中”的区别，并为后果设计可重复安全的提交步骤。
2. 移除 DLC 后读旧档，未知任务定义会 `addQuest` 返回 null；未知 NPC 不会按存档独立创建；缺失当前地区会回退到 `rbl`。再保存时只写当前存在的任务/NPC，可能丢掉那些扩展进度。证据：`Game.as:143–148,230–258,297–300,553–560`。这是静态推出的迁移风险，未做卸载实测；需要版本化项目存档片段与缺依赖检查，不能承诺“删掉 DLC 包就完全无痕”。

关键物品还应单独验证：原版用 `imp`、容器 `saveLoot=2`、领取回执恢复未拿的重要物品；存档回执是整个容器一项，不是每件任务物品独立一项（`S/fe/serv/Interact.as:1355–1388,1955–1996`）。同容器多件关键物品、只领一部分、退出再进应列为验收用例。

## 8. 建议的最小图形事件积木集合

以下是实现建议，不表示已经可用。用户用中文卡片、下拉对象选择和连线完成；原生属性名、AS3、XML 只出现在开发者诊断区。

| 用户看到的积木 | 最小字段 | 原生复用与新增要求 |
|---|---|---|
| 当……发生 | 进入区域 / 互动 / 单位被击败 / 获得物品 / 完成目标 / 选择回复 | 前五类有原生入口；“选择回复”新增事件。事件作用域及重复次数必须明确 |
| 仅当…… | 变量比较、任务/子目标、背包数量、技能/等级、地区状态；全部/任一/取反 | 原生有分散判断；可组合通用条件解释器需新增 |
| 只执行一次 | 本存档一次 / 每次进入 / 每次实例 | 封装持久键与实例键，不让作者混淆 `uid` 与 `code` |
| 某人说话 | 说话者、头像/表情、文本、多语言 | 原生顺序对白可适配；新头像需资产引用接入 |
| 玩家选择 | 多条回复、每条可用条件及锁定原因、默认取消行为、各出口 | 新增选择 UI 与运行状态；不能让“跳过对白”替玩家作选择 |
| 记住结果 | 设真假、枚举、增减计数 | 底层可借用 trigger 或版本化 DLC 存档域；一次后果提交要可恢复 |
| 更新任务 | 接取 / 显示目标 / 完成目标 / 本任务完成；指定任务/目标 | 原生 Quest 可适配。失败/放弃/互斥支线关闭需新增明确语义与显示 |
| 改变场景对象 | 对象选择器，开/关/解锁/启用/停用/消失 | 原生命令可封装；验证目标存在、对象类型支持，并恢复到后续房间实例 |
| 给予或扣除奖励 | 物品/货币/经验、数量、领取标记 | 复用 Item/Quest 能力；需要防重复、容量与关键物品策略 |
| 进入或开放地区 | 目的地、入口点、是否重建、返回点 | 复用 Land/Game；新地区目的地 UI、注册与进入时机需要原型 |
| 演出步骤 | 等待、镜头、朝向、音乐、角色移动/动画、控制锁 | 大部分可适配；需保证结束/异常/离场释放锁，不能拿静态预览认证演出 |
| 完成本段 / 跳到下一段 | 目标节点、提交点、章节结局 | 新增图执行和持久节点；循环次数与不可达分支校验 |

上述积木合起来应能让非程序员表达：“进入废弃站 → 没有帮助过守卫 → 守卫说话 → 选择帮忙或拒绝 → 记住选择 → 给任务或关闭这条邀请 → 开门 → 再次到访按结果出现不同人物”。它是一条建议的 DLC 示例，不是原版内容事实。

在编辑器内部采用同一套稳定 ID 的引用关系：场景中的 NPC ↔ 角色资源 ↔ 对话 ↔ 任务 ↔ 条件变量 ↔ 门/出口 ↔ 奖励。用户改显示名时整条关系不应断开；删除被引用内容时呈现具体受影响的事件，不能静默变成无目标命令。

## 9. 建议的第一个剧情运行原型验收

1. 一个独立测试 DLC 地区、两个房间、一名 NPC、一处门、一项分支任务；地图静态预览之外，进入隔离游戏实际行走和互动。
2. 两条回复产生不同任务/门状态；每条路径验证未满足条件时锁定原因，并确认“关闭对白”设置不会消灭选择。
3. 对话/演出结束恢复控制；重新进入 NPC、跨房、跨地区不重复给奖、不出现两个选项结果同时成立。
4. 各条分支分别在选择前、选择后、领奖后保存并读档；对关键物品只领一部分、掉地上、退出重进分别验证。
5. 把任务标题、对白文字改掉，旧档仍按原分支继续；改变内容结构时运行显式迁移；模拟依赖包缺失，说明恢复策略。
6. 当前地区未加载、目标对象不存在、图存在死循环或悬空出口时，编辑器导出前指出具体事件与修复点；运行时记录可读错误并释放控制。

不应先做大量事件节点皮肤再验证运行基础。最早的关键证明应是“一次选择能改变实际世界，保存退出再进仍然正确”，因为这决定后续所有分支剧情是否可信。
