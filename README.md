# 掉落工坊 0.1.0

用于 Remains 1.02 单人游戏的中文独立掉落编辑器。玩家不需要安装 Node、输入命令或编辑代码。

本版已完成程序与隔离验证；正式游戏连接尚未执行。

## 打开与使用

双击本项目中的 `dist\LootWorkshop\掉落工坊.exe`。请保留整个 LootWorkshop 文件夹，不能只移动 EXE。

1. 点击“复制原版，开始编辑”。原版方案始终只读。
2. 在“容器奖励”或“敌人战利品”中搜索对象。可以按共享奖励分类，也可以只改一个具体型号。
3. 选择“原版之外再增加”或“自定普通奖励”，添加物品，填写机会与最少/最多数量。两个数量相同就是固定数量。
4. 用右侧“试 1 次 / 100 次 / 1000 次”观察结果。这里使用虚拟数据，不会修改人物或存档。
5. 点击“保存方案”保留草稿；“应用方案”写入下次游戏启动读取的配置。
6. 初次使用还需点击底部“连接游戏”，阅读安装确认。保存退出游戏后再连接、重新启动；回来点“刷新状态”查看读取回执。

例如：想让弹药盒多出 6 发 10mm，选“弹药盒 → 原版之外再增加 → 添加奖励 → 10mm 圆弹”，机会填 100，最少和最多都填 6。

## 敌人额外弹药

进入“对应弹药”，打开“额外掉落对应弹药”。示例方案已经打开此功能；原版方案保持关闭。

- 默认按常规弹药包的 50% 发放：10mm 为 6 发，普通电池 10 发，火花电池 25 发。可改为固定数量、随机范围或其他百分比。
- 识别死亡前实际主武器的弹种；可将特殊弹种改回基础弹种。
- 原来的随机弹药、掉枪和拾枪赠弹仍然保留，所以总补给量会增加。
- 火箭、40mm 榴弹及野火核弹使用独立开关、机会与数量，默认关闭。
- 友军、近战、投掷手雷、法术、自动充能和无法识别弹药的武器跳过。可复活敌人普通倒地不发，最终结算仅发一次。是否掉枪不影响对应弹药。

这些默认数量是易于调整的起点，没有宣称已经完成长期平衡测试。

## 界面中的规则

“原版之外再增加”保留原版普通奖励，再独立抽取新增奖励；“自定普通奖励”换掉普通奖励层。地图指定道具、任务回执、死亡脚本与原本掉枪继续由游戏处理。

每条奖励单独判定机会，百分比不用合计为 100%。同一条奖励加入多个候选后，每次只从候选中选一种；“偏好倍数”越大越容易被选中。武器的件数与耐久分开设置。

具体型号优先于共享奖励。型号页的“继承整类设置”会移除该型号的单独规则，恢复继承；整类已被修改时，继承的是修改后的设置。

原版复杂的顺序分支、进度筛选、限额及保险箱生怪仍由原代码执行。自定义明确指定的物品不再经过随机池的进度筛选，但保留数量配额、货币加成和损坏损失；可以用“最早/最晚游戏阶段”限定出现阶段。重要物品标记不会被用来绕开配额。

目录覆盖本体 29 类容器内容、47 类敌人奖励、193 个共享分类/型号条目和 630 个物品条目。346 个条目配有从本机游戏导出的图标，其余使用类别图标。

## 保存、回退与卸载连接

- “我的方案”可以复制、改名、导入、导出，或打开方案文件夹。
- 撤销/重做适用于当前编辑过程；重启后恢复上次保存的方案与编辑位置。
- “打开上次应用方案”先打开上一份配置的副本供检查，点击“应用方案”才会生效。
- “恢复全部原版”清除当前方案的自定义普通奖励并关闭额外弹药；应用并重启后回到原版掉落行为。
- “我的方案 → 恢复连接前的游戏”卸载本次连接，保留方案和存档。先退出游戏。若主 SWF 后来被别的工具修改，自动恢复会停止，以免覆盖后续改动。

安装会在游戏根目录生成唯一的 `pfe_before_LootEditor_<时间与编号>.swf` 备份。不要删除这份备份或 `mods\LootEditor\backups` 中的安装记录。

连接沿用现有 ModLoader：安装本模块、登记为仅 1.02 启用，再调用原有扫描器。首次安装需要一次小范围掉落接口补丁；之后日常编辑只更新配置。安装包只接受本次验证过的游戏指纹，游戏更新或其他补丁改动后须重新适配。

“已保存”“已应用”“游戏最近一次启动已读取”是三个不同状态。最后一种需要游戏模块的配置指纹、读取时间及游戏目录回执相符。游戏内 ModLoader 设置页还可临时暂停掉落工坊。

## 当前边界

- 仅验证本机根目录 1.02 单人；没有认证 DLC 1.03/1.04 或联机掉落同步。
- 本体目录不自动包含其他模组新增物品。没有明确弹药字段的机器人武器跳过，首版没有手动指定机器人弹种的界面。
- 不编辑地图逐个容器的任务物品、陷阱、生怪、死亡脚本，也不创建新武器。
- 自定义普通奖励支持独立机会、候选权重、数量、耐久、重复抽取、阶段和精英条件；原版复杂条件作为整体保留，没有开放任意脚本或自编条件树。
- 预览显示地面生成，不包含拾枪赠弹、重复武器修理和地图指定奖励。批量试抽是估计，结果会波动；连续模式会累计配额消耗。
- 已做程序化实际操作和隔离游戏验证，尚未进行真人新手试用、长时间平衡游玩或所有敌人/地图的穷举测试。

## 开发与验证

源码：`desktop` 为桌面端，`src` 为游戏端。`src/tests` 及 LootProbe 只用于隔离验证，不进入正式模块。当前包约 383 MiB，包含独立桌面运行环境和针对本机的接口补丁，不是通用游戏分发包。

工具位置可通过构建脚本参数覆盖。开发者操作顺序：安装 package-lock 中的依赖；运行 `npm run build:ui`、`npm run check`、`npm test`；运行 `build/build.ps1` 编译模块、`build/bridge.ps1` 从已核验基线生成接口；用 `tools/run-game-test.ps1` 验证；最后 `npm run package`。

`tools/extract_catalog.py` 可重新提取本体目录。`tools/generate-fixtures.mjs` 生成两端一致性样本。游戏测试驱动需单独编译 `src/LootProbeDoc.as` 到 `build/out/LootProbeMod.swf`。`tests/ui.cjs` 通过本机 Playwright 控制真实 Electron；用 `LOOT_EDITOR_EXE` 指向打包程序。

不要安装 `build/out/pfe-loot.swf`：它只是编译供体。唯一可安装候选是通过方法保持检查的 `pfe-loot-safe.swf`。完整证据见 `knowledge/verification-2026-09-28.md`。
